How-To Guides

The common tasks. Each is one or two edits, by design.

Run it locally

The blog uses fetch() to load Markdown, which browsers block on file://. Serve over HTTP:

cd portfolio
python -m http.server 8000
# open http://localhost:8000/about.html

Non-blog pages also work by double-clicking the HTML, but the blog needs the server.

Write a new blog post

Two steps, no HTML:

1. Create  posts/my-first-build.md   and write it in Markdown.

2. Add one entry to posts.js (newest entries can go anywhere —
   the list is sorted by date automatically):

   {
     slug: 'my-first-build',          // must match the .md filename
     title: 'My First Build',
     date: '2026-07-01',              // YYYY-MM-DD, used to sort
     tags: ['Node.js'],               // optional
     readMins: 5,                     // optional
     excerpt: 'One line shown on the blog card.'
   }

The card on blog.html and the page at post.html?slug=my-first-build both appear automatically.

Add a nav link / a new page

Say you want a "Resume" page:

1. Create resume.html. Copy any content page (e.g. about.html) and:
     - set <body data-page="resume">
     - replace the <main> content
     - keep the <script> tags (chrome.js, script.js)

2. Add one entry to NAV in chrome.js:
     { page: 'resume', href: 'resume.html', label: 'Resume' }

The link now shows in the nav on every page, and highlights when you're on it. You do not edit the nav in any HTML file.

Add a theme

Add one object to THEMES in chrome.js:

{ id: 'midnight', ink1: '#e0457b', ink1soft: '#f0a6c2',
  ink2: '#3b46c4', ink2soft: '#9aa2ec' }

The theme button cycles through the array; the choice is saved in localStorage. No CSS change is needed — applyTheme() sets the ink custom properties for you.

Change the footer or social links

Edit the SOCIAL array in chrome.js. The footer is rendered from it on every page.

Adjust the look

All colours and shadows are tokens on :root in style.css. Change --paper, --ink-black, the --shadow* values, or the radius once and the whole site follows. Per-component tweaks live in their labelled sections of the same file.

Deploy

It's static — push the folder to any static host (Netlify, GitHub Pages, Cloudflare Pages, etc.). No build step. The blog's fetch() works on any real host because it serves over HTTP. Make sure posts/ and the CDN-loaded libraries (Font Awesome, Google Fonts, marked) are reachable.

Keep the knowledge graph current

After changing code files, the project convention is to rebuild the graphify graph:

python -c "from graphify.watch import _rebuild_code; from pathlib import Path; _rebuild_code(Path('.'))"
